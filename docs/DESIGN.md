# 干燥车间窑控系统 — 设计说明

## 1. 业务模型

```
树种 (species)
 └─ 基准版本 (schedule_version, draft → 发布后只读)
      ├─ 树种基础阶段表 (base stage rows)
      └─ 厚度等级覆盖 (overrides，只写与基础表不同的格)

窑 (kiln, 6 座，固定)
 └─ 运行批次 (run, 装料开跑时绑定“当时有效版本 + 厚度等级”，跑完为止)
      └─ 读数 (reading：干湿球温度 或 样板称重)
           └─ 阶段切换记录 (stage_transition)
```

### 两层基准

- **基础表**：按阶段号 1..N 排列，每行含进入条件 `enter_below`（含水率降到该值以下，%；第一阶段的进入条件留空，表示开跑即进入）、`dry_bulb`、`wet_bulb`。
- **厚度层**：按 `stage_no` 写覆盖格（三个字段任意组合，只写与基础表不同的），未写的格继承基础表。
- **合并预览**：服务端把基础表与某厚度等级的覆盖合并成一张有效表，每格标注来源 `base` / `override`，并对覆盖了进入条件的行标注。预览与发布后跑批时使用的有效基准是同一份合并算法（`domain/merge.ts`），保证“合并预览与发布后的有效基准一致”。

### 版本发布

版本生命周期 `draft → published`。只有 draft 可编辑/删除；`publish` 后整表冻结只读。每个树种至多一个 draft，至多一个 published。装料开跑时 run 保存 `version_id` 与 `thickness_grade` 快照，之后即使发布新版本，在跑的批次也一直按旧版本合并出的有效表跑完。

## 2. 计算模型（全部在后端）

### 2.1 干湿球温度 → 相对湿度

通风干湿球法（ventilated psychrometer，常数 A=0.00066 /°C，接近标准 0.000662），单位 kPa：

```
e_w   = 0.61094 · exp( 17.625·Tw / (Tw + 243.04) )      // 湿球温度下饱和水汽压（Alduchov–Eskridge）
RH    = ( e_w − A·P·(Td − Tw) ) / e_s(Td) · 100%
```

其中 P 取标准大气压 101.325 kPa，`e_s(Td)` 是干球温度下饱和水汽压。干球=湿球时 RH=100%。

### 2.2 相对湿度/温度 → 平衡含水率 EMC

采用 **Hailwood–Horrobin 吸湿模型**（1946），系数取自：

> Simpson, W. T. (1973). *Predicting Equilibrium Moisture Content of Wood.* USDA Forest Service Research Paper FPL 190.
> 亦载于 USDA Forest Products Laboratory, *Wood Handbook: Wood as an Engineering Material*, 第 4 章 Table 4–2 / Eq. (4–6)。

以华氏温度 T 与 RH（百分数 H）计算（百分数 MC 输出）：

```
W  = 330 + 0.452·T + 0.00415·T²
K  = 0.791 + 0.000463·T − 0.000000844·T²
K1 = 6.34  + 0.000775·T − 0.0000935·T²
K2 = 1.09  + 0.0284·T   − 0.0000904·T²
KH = K·H/100
EMC = 1800/W · [ KH/(1−KH) + (K1·KH + 2·K1·K2·KH²)/(1 + K1·KH + K1·K2·KH²) ]
```

参考值校验（`test/domain.test.ts`）：

| 条件 | 模型输出 | 参考值 |
|---|---|---|
| 20 °C / RH 65% | **12.00%** | 约 12.0% |
| 60 °C / RH 80% | **13.57%** | 约 13.6% |

两点均在 ±0.3 个百分点内。RH 超出 100%（湿球>干球属物理矛盾）在输入校验层直接拒收，模型不会收到非法数据。

### 2.3 样板含水率（绝干质量折算）

样板建立时给出初始称重与初始含水率（小数百分数），绝干质量：

```
m_dry = m0 / (1 + MC0/100)
```

任一次称重 m 时：`MC = (m − m_dry)/m_dry · 100%`。

题面校验：5000 g @ 60% → `m_dry = 5000/1.6 = 3125 g`；4062.5 g → `(4062.5−3125)/3125 = 30%`。

### 2.4 两次称重之间的含水率怎么估 —— 采用「保持上次值」(zero-order hold)

**选定方案**：在相邻两次称重之间，样板含水率保持上一次称重的折算值，直到下一次称重；只有称重读数能改变含水率，也只有称重读数能触发阶段切换。温湿度读数照常计算 RH 与 EMC 供曲线展示，但不参与进入条件判断。

**理由**：

1. 现场唯一被直接标定的含水率信号就是样板称重。烘干曲线外推必须额外假设干燥速率常数及其对温湿度的依赖（典型的扩散模型 τ(T,RH)、或 Simpson 干燥曲线表），这些参数需要按树种、厚度、窑况逐案标定；没有标定数据时，模型曲线给出的“及时”是以不可量化的偏差换来的。
2. 保持法的误差方向和大小是**可知且有界**的（见下），对操作工透明，验收也可复现。
3. 判定完全确定：同样一批读数无论按什么顺序、分多少次上报、是否重启服务，结果一致——这正是本系统的硬要求。

**误差来源**：

- 两次称重之间（本车间 2 h）真实含水率持续下降，保持值在区间内**偏高**。
- 样板代表性误差（样板与窑内料堆平均含水率的差别，通常是主要误差）与本选择无关，任何方案都存在。
- 称重仪表误差、样板掉角/污染。

**对阶段切换时机的影响：推迟（滞后）**。进入条件是“含水率降到阈值以下”，而保持值≥同时刻真实值，真实越过阈值的时刻发生在两次称重之间，系统到后一次称重才确认，因此切换时刻必然 **不早于** 真实越过时刻，滞后最多一个称重间隔（约 2 h，跨阈值的幅度越大滞后越短）。绝不可能提前。对干燥工艺这是安全方向：偏晚升温和降湿，带来的是能耗/时间成本，而不是开裂风险。

> 已记录的替代方案（未采用）：按当前干球/RH 推平衡含水率与扩散型干燥曲线（MC(t)→EMC 的指数逼近）。优点是切换更及时；缺点是依赖每树种/厚度的时间常数标定，标定错误会让切换**提前**（在未充分干燥时进入更苛刻阶段，正是开裂诱因）。后续若积累数据可作为每座窑的标定项引入，并与称重实测做残差校正；在那之前不把阶段判定建立在未标定模型上。

### 2.5 阶段推进判定

读数按 `(taken_at, record_no)` 排序后依次重放：

1. 进入阶段 1（起始）。
2. 每条**称重**读数得到样板 MC；若 `MC < 当前阶段进入条件`（第一阶段无条件），则推进；若一条读数连续越过多个阶段阈值，则为每个被越过的阶段各记一条切换，切换时刻统一记为**该称重读数时刻**（越过的真实时刻不可知，记首个观测时刻，与 2.4 的“推迟”口径一致）。
3. 阶段只进不退。最后一个阶段之后不再切换。

### 2.6 乱序、重复与重启 —— 事件溯源式重放

- 所有读数按 `record_no` 唯一约束入库（`record_no` 全库唯一）；重复上报返回 **409**，不产生任何状态变化。
- 任何一条读数入库后（包括时刻早于历史读数的“晚到补录”），该批次的切换时间轴都**从零按时刻顺序重放**全部读数重建。因为阶段判定是读数集合的纯函数（与插入顺序无关），乱序上报与顺序上报得到的每条 `stage_transition` 的 `阶段号、切换时刻` 完全相同。
- 切换记录是重放结果，可整体删除重建；服务重启后从 readings 表重放恢复，状态不丢不重。run 的 `current_stage` 也是派生值，随重放更新。

切换时刻相同性的排序规则：读数先按 `taken_at` 升序，同时刻按 `record_no` 升序（记录编号是全库递增的上报序号，同时刻时先报的先处理，确定且无歧义）。

## 3. 校验规则（全部拒收 400 并指出字段；引用不存在的窑/树种/版本为 404/400）

| 规则 | 字段 |
|---|---|
| 0 ≤ 干球 ≤ 120 °C | `dry_bulb` / `dryBulb` |
| 0 ≤ 湿球 ≤ 120 °C 且 湿球 ≤ 干球 | `wet_bulb` / `wetBulb` |
| 称重 > 0 | `weight_g` / `weightG` |
| 进入条件（除第 1 行留空外）必须逐行**严格递减** | `enter_below` |
| 温/湿度相关数值 NaN/缺失也拒收 | 对应字段 |
| 引用不存在的窑 | `kiln_no`（404） |
| 引用不存在的树种/版本 | `species_code` / `version_id` |
| 已发布版本只读 | 版本本身（409） |
| 窑无在跑批次时上报读数 | `kiln_no`（409） |
| 读数时刻早于开跑时刻 | `taken_at` |
| record_no 重复 | `record_no`（409，幂等） |

错误响应统一形如：`{ "error": "...", "fields": ["wetBulb"] }`。

## 4. 技术架构

- **后端**：Node.js 20 + TypeScript（strict）+ Fastify 4，pg 直连 PostgreSQL 16，迁移 SQL 启动时自动执行。领域计算（RH/EMC/合并/重放）全部是纯函数，位于 `server/src/domain/`，不依赖数据库，可直接单元测试。
- **前端**：Vue 3 + Vite + TypeScript，无重型 UI 框架；曲线用内联 SVG 自绘。页面只做编辑与展示，不含任何业务计算。
- **部署**：多阶段 Dockerfile（node:20-alpine）构建前端并由 Fastify 托管 `web/dist` 静态文件；与 `postgres:16-alpine` 同一份 `docker-compose.yml` 启动，健康检查通过后再启应用。
- **测试**：Vitest，领域纯函数全覆盖（两个 EMC 参考值、样板折算、合并来源标注、乱序/顺序等价、重复幂等、重启恢复、各校验项）。

## 5. 关键 API

```
GET/POST            /api/species                 树种
GET/PUT/DELETE      /api/species/:code           draft 编辑
GET/POST            /api/species/:code/versions
GET                 /api/versions/:id            含 base/overrides/merged
PUT                 /api/versions/:id            编辑 draft
DELETE              /api/versions/:id
POST                /api/versions/:id/publish    发布冻结
GET                 /api/thickness-grades        厚度等级字典
GET                 /api/kilns                   六座窑
POST                /api/kilns/:no/start         装料开跑（绑定有效版本）
POST                /api/kilns/:no/finish
GET                 /api/kilns/:no/state         当前阶段 + 时间轴 + 曲线数据
POST                /api/readings                上报读数（含手工补录）
GET                 /api/kilns/:no/readings
```
